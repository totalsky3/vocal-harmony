# VocalHarmony

**歌声にリアルタイムでハモリを付ける / 声をキャラクターボイスに変える、C++製のリアルタイム音声処理ツール。**

マイクに向かって歌うと、曲のキーに合ったハモリが本人の声質のまま重なって聞こえます。同じ音声処理基盤から、TRPG のセッションなどで使えるボイスチェンジャーも派生させています。

---

## 概要

このプロジェクトは、音声を「ソース(声帯の振動 = ピッチ)」と「フィルター(声道の共鳴 = フォルマント)」に分離して独立に操作する、いわゆる **ソース・フィルター理論** を実装の土台にしています。この2軸を別々に動かせる基盤を作ったことで、パラメータの与え方を変えるだけで用途の異なる2つのアプリケーションが成立します。

| アプリ | 内容 |
|--------|------|
| **ハモリ生成** (`main.cpp`) | 入力音声の基本周波数(F0)をリアルタイムに検出し、曲のキー/スケールに合った「スケール準拠のハモリ音」を計算して重ねる。男声の上ハモリが破綻しないよう、音域に応じた自動オクターブ補正も行う。 |
| **ボイスチェンジャー** (`voice_changer.cpp`) | ピッチとフォルマントを独立に操作してキャラクターボイスを作る。数字キーでプリセット(巨漢・怪物・少女など)を即時に切り替えられ、仮想オーディオデバイス経由で Discord 等に出力できる。 |

開発は「Python でオフラインに原理を検証 → C++ でリアルタイム化」という順序で進めました。その検証用スクリプトも [`offline-prototype/`](offline-prototype/) に残してあります。

## 技術スタック

- **言語**: C++17
- **オーディオ基盤**: [JUCE](https://juce.com/) — クロスプラットフォームのオーディオ入出力・デバイス管理
- **F0(基本周波数)検出**: [aubio](https://aubio.org/) — YIN アルゴリズム
- **ピッチ/フォルマントシフト**: [Rubber Band Library](https://breakfastquay.com/rubberband/) — リアルタイムモード
- **ビルド**: CMake + vcpkg (Windows) / pkg-config (macOS・Linux)

## 設計のポイント

ポートフォリオとして、単に動くだけでなく「リアルタイム音声処理特有の難しさ」にどう対処したかを重視しました。

### 1. 音楽的に正しいハモリ(diatonic スナップ)
単純に固定の半音差で平行移動させると、コード進行に対してスケール外の音が生じて不協和になります。本実装では各音をキーのスケール上の最も近い音にスナップさせることで、「3度上」が自動的に短3度と長3度の混在になる、音楽理論的に正しい挙動を実現しています。

### 2. 男声でも破綻しない音域調整
ピッチシフトで上ハモリを作ると、男声では自然な音域(声区)を超えて不自然になりがちです。ハモリ音が快適音域を外れたらオクターブ単位で補正することで、和声的な正しさ(音名)を保ったまま聞きやすい高さに収めます。これは市販のカラオケ機器のハモリ機能を実際に使って感じた課題から着想した機能です。

### 3. リアルタイム制約への対処
- **スレッド間の安全な値受け渡し**: オーディオコールバックと表示スレッドの間は `std::atomic` でロックフリーに共有
- **コールバック内でのメモリ確保回避**: バッファは事前確保し、時間制約のあるコールバック内では確保・解放しない
- **外れ値への多層防御**: F0 検出が稀に出す異常値を、範囲チェック・比率クランプ・更新間引きの三段で防ぐ
- **因果的な外れ値対策**: オフラインで使えた中央値フィルタ(未来のサンプルを要する)の代わりに、「信頼度の低いフレームでは直前の確かな値を保つ」方式を採用
